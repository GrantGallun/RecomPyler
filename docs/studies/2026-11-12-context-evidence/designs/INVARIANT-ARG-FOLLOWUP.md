# Follow-on only: invariant recursive semantic arguments

This is a distinct hypothesis after the strict five-context-scalars-to-one-pointer experiment. It is not part of the stage-one product scope and has no executed compilation or timing evidence.

In the saved actual force source, all four self edges pass `np.int64(v_particle)` and `np.float64(v_theta)` unchanged; only the child/self handle varies. If those values are captured in an activation-local environment, the recursive body can accept `(activation_pointer, self_handle)` plus Numba's hidden result/exception pointers. Those four physical positions fit the current Windows register ABI and predict zero outgoing stack arguments. That is interface parity with C's four physical arguments, not layout/arithmetic/check/latency parity.

Use an external-entry wrapper with the current full borrowed signature. It allocates a private `{heap_context_pointer, particle, theta}` record in its own native frame, initializes it once, then calls a new self-recursive body. Internal self edges call that body directly; outside callers call the wrapper and receive a fresh activation. This is necessary because the enclosing advance entry calls force for many particles: storing particle/theta in one whole-region heap context would mix separate invocations. A mutable global or one reused context field would also fail reentrancy. Nested/recursive external activations must each retain independent environments until their corresponding body returns.

The first general rule should handle self-recursive functions only, requiring every recursive edge to forward the exact original formal machine scalar for each captured position. A generated-source implementation can be conservative: accept only original formal names with no assignments to those names anywhere in the body, permitting only compiler-inserted casts proven to be identity at the already-settled machine type. A mere identical AST name is insufficient if the formal was rebound earlier. A stronger later implementation can use SSA reaching definitions. Do not infer invariance from test values, algebraic equivalence, equality observed at runtime or just one recursive branch. `x + 0`, arbitrary casts and NaN/signed-zero-sensitive rewrites are not automatically identities.

All recursive call sites must be known and rewritten, including ones in branches. Preserve parameter binding/evaluation order and type specialization; the wrapper receives fully evaluated arguments and captures their machine representations without additional arithmetic. Tuple/optional values are captured only as their complete settled machine-value groups. Result shape, numeric-kind bits, nullable flags, error sites and recursion bookkeeping remain unchanged. The activation pointer must have a private internal type/API so callers cannot confuse it with the original heap context pointer.

Capturing an object/list handle is not capturing its fields. The object behind a handle can still mutate or alias another input; every original field/header load remains semantically required unless separately proved redundant. Invariant particle/theta capture cannot justify caching coordinate, kind, mass or child fields across recursive calls. Growth exits require the same unwind/retry discipline; the activation environment is discarded and reconstructed on a new external entry with the new heap context.

For mutually recursive SCCs, names and argument positions can differ or permute. A sound extension needs a fixed-point parameter-flow relation across every SCC edge, preserving machine types and a consistent entry-to-body mapping for each external member wrapper. A member may receive a varying argument in one path even when another member forwards a same-named value. Capturing dummy arguments from the merged-SCC representation can accidentally retain the wrong member's state. This makes self-recursion-first a useful bounded experiment; SCC-wide invariant capture deserves a separate specification and tests.

Required counterexamples include a rebound formal; a changed argument on only one recursive branch; two external invocations with different invariant values; nested activation/reentrancy; tuple/nullable fields; mixed integer/float kinds; signed zero/NaN payload preservation; growth retry and exception rollback; mutable objects behind captured handles; and mutual recursion with argument permutation or a noninvariant edge. Actual assembly must prove one wrapper record allocation per external activation, no record reconstruction at self edges, no lost status/depth/kind checks, and the predicted two-to-zero outgoing slots in force. Check whether extra environment loads increase instruction/spill/frame costs before drawing any performance conclusion.
