# Preserve heap SSA values through always-inlined helpers

This is one representation follow-up to frozen57835fa8a89d0d846e291abc7f9f6f335aa272a8, preserving its ordinary-iteration proof and strict Python behavior. Preserve the previous candidate, full validation, checkpoint and measured cohort. No new heavy test/build/profile/benchmark has been authorized or executed for this design.

## Measured reason for the change

Fresh manifestd058c448e449e26f405b9f1d5f508291ab61227500d9e6b9a66e564ea57d2806 measured Barnes35.1749→33.0258ms (-6.11%) and raytrace3.6208→3.8761ms (+7.05%), with every paired ray sample worse. Independent actual assembly shows Barnes force334→316 static lines and six→two outgoing slots, while ray render997→1180 nonpadding instructions and recursive SCC2508→2807. The descriptor unpack inserted in every helper becomes repeated descriptor loads after those helpers inline across arena/status writes. These counts locate a plausible regression mechanism; they do not assign cycles or prove that this follow-up will remove the timing regression.

The target is avoiding unnecessary descriptor re-reads inside helpers already promised inline, while preserving the compact interface at actual recursive/large/entry boundaries. It is not a new alias/effect proof or field-value cache.

## Exact bounded rewrite

At `_borrow_heap_context`, inspect each original generated source's exact decorator prefix before AST rewriting and before `_plain` replaces decorators. A function is a raw-SSA helper only if its prefix equals `_INLINED`. Do not substitute `not info.recursive`: `_Gen.generate` currently marks a helper inline only when it is nonrecursive, is not the entry and has at most INLINE_LINES generated lines. `_merge_cycles` also emits inline wrappers, including potentially an entry wrapper. Merged SCC dispatchers remain ordinary `_DECORATOR` functions.

- Every borrowed body still accepts `_heap_ctx` first, so helpers can forward it to recursive/large callees.
- A body with exact `_INLINED` marker accepts the five existing raw scalar values next: `_heap_F`, `_heap_I`, `_heap_top`, `_heap_st`, `_heap_len`. It reconstructs F/I/top/st carray views from these values and **does not call `_heap_context_unpack`**.
- Every other body keeps its current `(ctx, semantic...)` signature and unpacks exactly once at entry, then reconstructs its local views as before.
- Every known generated call is rewritten using the **callee's** original marker: ctx+five raw values for an inline-marked callee, ctx alone for other callees. Calls between inline helpers, inline wrappers to SCC dispatchers, recursive bodies to inline helpers, and inline helpers to out-of-line recursive bodies all use the same rule. Preserve semantic argument order/types and the existing exact decorator spelling.
- The public array adapter retains its existing signature and validation order. After validation, initialize each raw pointer plus the int64 arena length once, then pack the same single typed tuple-pointer descriptor from those values. Invoke its borrowed entry using that entry's marker. Thus an entry changed into an inline SCC wrapper receives the raw five values without undefined local names. The normal noninline entry still receives only ctx.
- Runtime helpers outside the known generated function map retain their existing interfaces. Nonrecursive regions still use their existing path. No changes to cycle merging, inline eligibility, numeric/status/error/recursion lowering, public validation, ownership or retry logic.

The tuple-pointer schema and pack/unpack intrinsics remain unchanged. Actual low-level pointer dtypes are preserved. No new global state, custom type, registry, alias scope, noalias, readonly, invariant.load or field/effect metadata is introduced.

## Why this is sound

The raw five values are immutable addresses/arena length for one synchronous native attempt, already unpacked by an enclosing body or obtained by the validated public adapter. Passing them does not copy or freeze their pointees. F/I still share storage; arena/top/st contents can change and all original loads/stores remain. Arena growth still exits the attempt before any resize; the next adapter call initializes fresh values and descriptor. Descriptor lifetime remains the public adapter's dynamic lifetime. No pointer is retained or returned to Python.

The widened helper signature is intended to disappear under existing AOT always-inlining, leaving the caller's original SSA pointer values available after writes. `_plain` intentionally changes those markers for JIT/profiling, so the JIT path will retain wider helper calls. That is an explicit performance tradeoff requiring observation of profile/startup/native costs; it does not change semantics or justify classifying extra helpers as inline. An always-inline hint alone cannot establish an instruction/time gain.
