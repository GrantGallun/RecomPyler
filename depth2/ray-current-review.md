# Current-ray diagnostic ablations: independent source review

Reviewed ray_current_common.py, ray_current_build.py and ray_current_native.py as default-input diagnostics, not compiler rules. No build, render, native execution or timing cohort was run. Static parsing passed for all three files. Inspected the frozen numeric-final-v2 compiler snapshot and the prior numeric-final-v1 generated list/tuple shape; final-v2 native artifacts do not yet exist and are a launch prerequisite.

## Concrete launch blocker

The current-mode source gate compares sha256(p.source.encode()) with sha256(r0.generated.py.read_bytes()). On this Windows workspace the existing numeric-final-v1 generated source has 5,170 CRLF line endings, while read_text().encode() normalizes them; the hashes differ for identical source text. The final-v2 artifact writer may produce the same form. Normalize the saved generated source with read_text().encode(), or require an explicit LF-byte writer and retain the exact normalized source/digest check. Reported this before launch. The other modes compare the stored source_sha256 computed from p.source.encode() against the newly generated same representation, so that particular line-ending mismatch does not affect them.

## Capacity and fused storage

The fixed scene has eight objects and two lights. rayColour constructs exactly one intersection tuple for each stable object-list element, and visibleLights appends at most once per stable light-list element. Preallocating their respective capacities from those lengths is sufficient for this scene. The checked list_room helper increments length before returning the append slot, so after append j the replacement tuple address D+n+4*(length-1) selects the jth four-slot tuple block.

With tuple fusion, list_new reserves 5n slots starting at D, then a separate three-slot list header. Resetting the advertised capacity to n leaves list data in [D,D+n), followed by tuple blocks [D+n+4j,D+n+4j+4), j=0..n-1. Those intervals do not overlap each other or the header. The actual tuple retains its object handle, float payload, optional flag and surface handle stores through the existing shared F/I arena views; payload/tag layout and list element handles remain unchanged. Independently checked this arithmetic for n=0..16. It is essential that physical reservation remains 5n even though logical capacity is n.

The transformation runs before merge/context rewriting, so current original/scalar clone bodies are transformed before recursive names are prefixed. Each invocation obtains a fresh bump-allocated block, and recursion cannot reuse an earlier invocation's block. Source assertions require one matching creation and, for tuple mode, one four-slot bump per transformed rayColour body. Existing generated order is list_room, its status check, tuple address, payload stores, then list-pointer store; the replacement relies on that order and on v__c0_list retaining the local list handle. The visibleLights change retains filtering and append order.

These are known-valid restrictions: stable scene lists, fixed layout offsets, no user method mutating those lists, nonnegative small cardinalities and adequate arena capacity. In tuple mode the capacity-header write occurs immediately after list_new and before the existing status check; an allocation failure could therefore write through the failure handle. That behavior precludes treating this as a generic checked rewrite or supporting small-arena failure/replay experiments unchanged. The planned successful default-input diagnostic, direct status gate and ample arena are the applicable scope. No failure-path equivalence claim is cleared.

## Native identity and output gates

SourceOnly analysis prevents a JIT fallback while preparing the program. The build names each module with the mode and program digest, exports the typed original entry ABI on a generic CPU with fastmath disabled, and records source hash, digest and diagnostic report. The native runner regenerates the exact program, checks the digest and normalized-source identity, loads the named extension directly and assigns its export to p.run. Each repetition deep-copies inputs, restores loader values/blocks, initializes depth/status state, calls the native export once, checks clean status, writes back and checks the full canvas SHA256. The final absence-of-numba check supports a native-only runner. Pixel gates must pass for every mode; no build/source rewrite alone establishes equivalence.

The current artifact path must be built only after final-source validation; its missing directory is presently a prerequisite, not permission to substitute an older module. Baseline-versus-preallocation and preallocation-versus-tuples isolate different increments. Float constructor variants also change logical kinds and resulting ABI/storage, so describe them as known-input float-layout diagnostics, not isolated machine arithmetic speed. Five minima are diagnostic observations, not acceptance evidence or a noise-resolved gain. Build and measurement launches still require the outer shared timing-lock protocol; these scripts do not acquire that lock themselves.

## Partial call/ABI ablation

The inspected prior optimized native IR already contains the public entry, borrowed render body and surviving merged recursive rayColour/colourAt function; ordinary scalar helpers have been inlined. Merely forcing alwaysinline on acyclic surviving internal callees is an honest partial ablation only if a real remaining edge disappears. It cannot demonstrate removal of recursive call overhead or explain a zero delta as absence of call cost.

The proposed constant-which SCC split is also a defensible diagnostic: clone the merged native function for selectors 0 and 1, replace only the selector formal's uses by the matching literal, retain the full checked ABI/status/arena semantics, and redirect only proven constant-selector calls. Preserve an original path for any other selector/call use. After branch elimination, selectively inline the colourAt clone while retaining the recursive rayColour path. Do not add noalias assumptions for F/I, fastmath, or new semantic attributes; preserve calling convention and return-slot types. Remove conflicting noinline only for the intended target, and verify the module.

That intervention can expose constant propagation, dead packed-result slots and surrounding memory/check simplification as well as removing a call. Report it as a partial call/dispatch/ABI ablation, not a pure call-latency measurement. A matched unmodified reoptimization replay control, identical codegen options, complete-pixel gate, and pre/post optimized IR proving the targeted edge and packing reduction are required before interpreting a measurement. Recursive residual calls remain unclosed. No timing, edge-removal or gain claim is made by this review.

## Streaming record/minimum diagnostic follow-up

Reviewed ray_stream_diagnostic.py and its float-stream wiring. The replacement retains the original ordered object traversal and all intersectionTime calls; it removes private tuple/list materialization and the separate firstIntersection traversal, not object traversal itself. Five per-call locals represent the same flattened optional result: object handle, distance payload, distance-present flag, surface handle and selected-record-present flag. Initial no-hit state has the record-present flag False, so the existing background/no-result branch remains authoritative.

Selection accepts only present distances greater than -1e-5, matching the original EPSILON threshold, and replaces an existing best only on strict less-than. Equal distances retain the first object in traversal order, including signed-zero ties; NaN distances fail the threshold comparison and positive infinity follows the same ordinary comparison rules. None distances short-circuit on the present flag. The comparison moves between primitive intersection results, but default typed distances are float/None and the comparisons have no user effects or throwing conversion. All later object intersection calls still run in order. This is not a generic custom-comparison or allocation-failure equivalence claim.

The min locals are initialized separately for each function invocation before object traversal; recursive merging's existing Store-name renaming keeps them local to that invocation. The original recursion-depth increment, early depth-limit return, selected-surface calls and final decrement are outside the replaced blocks and remain. Existing post-intersection status exits remain; the deleted list/record allocation status checks are intentionally absent under the adequate-arena known-valid diagnostic scope. The remaining check after the former consumer call is harmless.

Shape assertions require one creation, the expected list_room/alloc/four payload stores/list-handle store sequence, one five-slot consumer and no surviving list variable. Independently applied the transform to the existing final-v2 generated f30_rayColour body and reparsed: no list_new/list_room/alloc calls or firstIntersection call remained, no private list reference survived, and all five min locals were initialized. No body was executed. Source review found no concrete None/record/tie/recursion error. Native full-pixel and counter-off/on/highwater gates remain mandatory before the new variant joins a cohort.

The call-ablation source origin and native body-mode check now both use float-stream.
