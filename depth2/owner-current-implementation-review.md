## Proof and physical ownership

copy_owner requires a full [:] copy between fixed private local arrays, both names in current control-flow environment, both with existing F3 earlier top-level initialization lines, and both retaining the same permutation extent. The provenance is global over every creation/rebinding and slice store, not merely a statement-local nominal length. Its range roots are guarded nonnegative bounded list(range(0,n)) constructions, and full-copy dependencies preserve physical lengths and int64 dtype. Foreign element stores, extent-changing slices, unsupported constructions and unknown/branch-only owner initializations do not acquire this certificate. Captured methods and old list iterators remain excluded by existing F2/F3 logic.

The earlier-owner line check supplies dominance; control-flow environment presence prevents assuming a local is available merely from global metadata. Later conditional same-extent fresh rebinding remains safe because every admitted creation has the same physical extent and private unobserved identity. The direct emitter is additionally restricted to an actual existing _rc_copy_reuse site. A proof answer on some other assignment cannot turn a new/uninitialized target into a borrowed copy.

F9 is a per-copy failure-free answer, not whole-function failure freedom. copy_into ignores status, so the physical extent proof must hold even when a preceding checked operation has set status. Under these constructor bounds, range endpoint arithmetic is safely/raw emitted, arange has fixed nonzero unit step, and the constructor helper still returns the requested extent despite an unrelated existing status. Full-copy initialization likewise preserves the physical source extent. Permutation rotations retain array shape; invalid checked rotation exits without a size change. Allowed validated prefix flips retain shape. Allocation exceptions leave the function rather than continuing with a wrong-size owner. Thus prior status does not turn one of these buffers into a differently sized dummy before the direct copy.

The helper accepts exact same-kind one-dimensional arrays and loops over source length into target; both buffers are the same guarded length and dtype. No allocation or owner assignment occurs at the certified site. Private identity/alias exclusions justify retaining the old target owner. Ordinary initial allocations, fallback copy_fits/fresh-copy paths and Numba exit cleanup remain unchanged. F1/F2/F3/F9 declarations and per-site rule reports match this implementation; source clearance does not prove every hot-loop NRT operation has disappeared.
