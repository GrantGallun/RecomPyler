# Installed AOT and reuse source review

Installed Numba is **0.68.1**, llvmlite **0.50.0**, CPython **3.14.4**. This is the installed environment, not an inference from current documentation. Installed `numba/pycc/__init__.py` emits `NumbaPendingDeprecationWarning`: ?The 'pycc' module is pending deprecation. Replacement technology is being developed.? The same warning says pending deprecation started in0.57.0; there is no removal in this installed version. [Numba deprecation documentation](https://numba.readthedocs.io/en/stable/reference/deprecation.html#deprecation-of-the-numba-pycc-module) explains the limited AOT feature/linking path and setuptools dependence; pending removal is not the deprecation of Numba's compiler/runtime.

RecomPyler's `src/recompyler/_pycc` vendors the0.65.1 CC, compiler, toolchain and module-wrapper layer under BSD2-clause terms. Its source documents relative-import changes, installed-Numba header/runtime source paths, and omission of legacy export decorators and the pycc import warning. It compiles exported functions using `numba.core.compiler.compile_extra` and links runtime sources from installed Numba, including `_nrt_python.c`. It does **not** replace Numba's type system, nopython compiler, NRT, LLVM, or every future internal API dependency. The copied builder remains available independently of the deprecated `numba.pycc` import path; this is not proof of indefinite compatibility.

PIXIE has a **development release**, not zero releases: official PyPI JSON reports `numba-pixie`0.0.1.dev0 with two files; the official repository has tag0.0.1dev0 at83122c714b041da8f8c5a3e7eeb1a108fb71549e, while its GitHub Releases endpoint is empty. Evidence retrieved2026-11-14 is in `pixie-release-check.json`. The released package requires llvmlite>=0.39,<0.43, incompatible with this installed0.50.0; current repository metadata instead asks >=0.44.0dev0,<0.45, also incompatible. [PIXIE project metadata](https://github.com/numba/pixie/blob/main/pyproject.toml).

[Official PIXIE documentation](https://numba-pixie.readthedocs.io/en/latest/) lists x86-64 Linux and arm64 macOS support. This workspace is Windows x86-64. PIXIE consumes LLVM IR/bitcode (or C/Cython translated to it), builds libraries with CPU dispatch and embedded bitcode, and provides export configuration; it is not an automatic Python-function-to-AOT replacement for CC. Its `TranslationUnit`/`PIXIECompiler` source was read through the official repository. Therefore the development release is not a usable drop-in replacement here without a Windows port, LLVM/toolchain adaptation, and frontend/boxing/export integration. No install or trial build was performed because S35.3 is a source-only review. [PIXIE compiler](https://github.com/numba/pixie/blob/main/pixie/compiler.py), [PyPI metadata](https://pypi.org/pypi/numba-pixie/json).

`numba-passthru` has a small BSD2-clause source implementation (license retained in vendor/LICENSE.numba-passthru). PR3640 was closed unmerged in2023; it is not built into this installed Numba. Its unchanged package import was actually attempted and fails on removed `llvmlite.llvmpy`. The reusable part is its StructModel carrying an NRT MemInfo whose owner is the original PyObject, with custom box/unbox. Operations still need typed intrinsics/overloads; the package alone does not make arbitrary Python operations nopython. The experiment adapts that model and uses installed `pythonapi` helpers. [Upstream package](https://github.com/asodeur/numba-passthru), [PR3640](https://github.com/numba/numba/pull/3640).

Prototype development exposed a second compatibility issue: installed `pythonapi.string_from_constant_string` calls the legacy missing PyString_FromStringAndSize symbol. The first owned execution crashed; the experiment now uses current `string_from_string`, which emits PyUnicode_FromString. The failure and emitted LLVM are preserved. This is a compatibility correction inside the experiment, not a change to installed Numba or product sources.
