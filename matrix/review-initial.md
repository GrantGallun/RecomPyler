# Independent initial matrix harness review

Reviewed 2026-11-14. Scope: catalogue.py, run_matrix.py, run_locked.py, and the public candidate/wrapper contracts needed to interpret their observations. No suite, construct, build, profile, or timing workload was run for this review. The examples below are harness counterexamples to exercise, not compiler verdicts inferred from source. Full-cohort acceptance should wait until the classification and fixture issues below are fixed and the two-program/construct smoke has been checked.

## Blocking findings

1. **A mismatching fallback can receive a declined verdict.** run_matrix.py:118-123 chooses declined whenever native_calls is zero, even when got differs from plain. A wrapper which falls back after duplicating an event, mutating an argument, or changing a global can therefore produce verdict=declined with reason=compiled replay differs. Compare behavior first: any mismatch must enter the defect path, retaining execution accounting so the report distinguishes a native discrepancy from a fallback/capture defect. Only identical Python execution with an observed named decline is declined.

2. **Ordinary generator invocation cannot establish native generator coverage.** run_matrix.py:119-120 drives wrapper(*args). Region.__call__ deliberately returns the original Python generator for generator flags; its native draining entry is Region.values, used by profiler._region_values. Thus a candidate verified through native draining can be reported declined here. Exercise the same ordinary draining adapter as the product, and retain both yielded sequence and StopIteration.value. Do not claim generator return-value support merely because the values-only adapter matches the yielded prefix. Add one sync generator with a non-None return and one async generator.

3. **Two builtin fixtures fail before invoking the builtin.** catalogue.py:137 references AsyncRange in builtin.aiter and builtin.anext, but bsetup at :149 contains no AsyncRange definition. Fix setup and consume/await the result. Returning only type(anext(...)).__name__ does not execute __anext__; it also creates an unawaited coroutine and may produce nondeterministic warning output. Add exhaustion/default cases. UnicodeDecodeError, UnicodeEncodeError, and UnicodeTranslateError also need their required multiargument constructors; defaulting all exception constructors to one string tests a constructor TypeError rather than the advertised type.

4. **Native disagreement vs internal crash is inferred from English text.** run_matrix.py:113-116 maps every rejected reason containing differ to wrong, everything else to crash. profiler._test_region/test_lifted use rejected for both result disagreements and a captured call raising when replayed. A compiled implementation that raises ValueError instead of returning 4 is a behavioral discrepancy, but this harness labels it crash. Conversely a candidate rejection need not establish that any native instruction executed. Record phase, actual exception/result, native-attempt/success evidence and compiler-error evidence separately; classify from those observations. Preserve unknown/instrument failures as harness errors until repaired instead of polluting product crash totals.

5. **Lifter compilation/runtime exceptions can be swallowed without a crash record.** lift._prepare catches its compile-error class and generic Exception; Lifted.__call__ also catches Exception around _run and falls back. Region.programs[].broken only covers region failures, so probing a separate region does not expose an earlier lifter error. A harness-only trace observer can collect exception events in _prepare/_run during candidate/probe execution, preserving/restoring the previous trace and allowing successful retype recovery. An unresolved compilation exception followed by fallback must be visible, with original type/message/phase, rather than rewritten to a generic runtime guard decline. Do not treat successfully recovered speculative compilation as a final crash.

## Comparison and coverage findings

6. **Opaque comparison can certify unequal behavior, and alias relationships are lost.** run_matrix.py:42 treats every unrecognized pair of values of one type as equal. Unknown types should require an explicit safe projection or fail the harness. Also result and arguments are frozen with separate memo tables (:73,:76), so returning an argument and returning its independent copy compare identically. Freeze result, argument poststate, and observed fixture state together with one memo table to check alias relationships. Useful concrete safe projections:
   - classmethod: install on a fixture class and call through class/instance, returning the actual binding result;
   - staticmethod: call through class and instance;
   - property: access through a fixture instance and return getter result;
   - compile: evaluate the harmless compiled expression and return its result;
   - super: use a Base.read and return super(Box, box).read();
   - memoryview: format, itemsize, ndim, shape, strides, readonly, and bytes;
   - template: strings and each interpolation's value, expression, conversion, format_spec.
   The existing type-name summaries for these constructors do not exercise their advertised semantics.

7. **Exception chaining and evaluation order need executable witnesses.** exception() records cause but ignores __context__ and __suppress_context__, so raise ... from None and implicit chaining can compare equal despite different behavior. Add explicit/implicit/suppressed chaining cases. Most operands and arguments are constants, so the harness cannot observe reordered calls or short-circuit evaluation. Add inert EVENTS-appending operands for comparison chains, and/or, conditional expressions, argument evaluation, unpacking, dict key/value evaluation, context-manager enter/exit and exception cleanup. Compare events as well as return/exception.

8. **Catalogue token/AST presence is not construct coverage.** inventory() traverses all setup helpers, not only construct and its reached nested bodies; that can credit nodes merely defined in setup. It also records keyword spelling without its syntactic role. Keep the inventory, but give every required role an explicit row and execution witness. Specific missing/ineffective rows: except E as name; bare except; slice assignment (literal.slice_store only returns a list); async with multiple managers; nonempty caller-supplied **kwargs (call.varkw currently receives none); caller-supplied keyword-only arguments; chained comparisons whose later comparisons actually execute; f-string !s/!r/!a on a value where conversions differ (x=3 hides the distinctions); str.format/format_map with actual replacement fields. Add targeted error and boundary inputs alongside nominal cases, especially int overflow, zero division, negative shifts, and sequence bounds. Current one-input verdicts must be labeled input-specific.

9. **Stdlib selection is handpicked rather than justified by existing profile call counts.** catalogue.py:184-190 contains an explicit small list, with no profile provenance or assertion that every hot entry in the named modules is represented. Every public method is generated, which exceeds the method minimum, but still needs the requested existing-profile counts and held-out time mapping. Before the full cohort, derive/check a callable inventory from existing wave14 profiles, record unmapped entries explicitly, and add missing hot entry points. Do not infer time from AST/token counts.

## Safe execution / lock robustness

10. **No per-row isolation or timeout.** One native infinite loop, fatal extension fault, or blocking builtin prevents all remaining rows from producing results and may hold TIMING.lock indefinitely. Run each row under a parent-owned child process with an explicit reasonable timeout, record its exit status, and terminate only that run's own timed-out child tree. The parent should retain the lock until owned children are gone and emit a crash record/continue. A failed row must not erase earlier evidence.

11. **Lock cleanup does not cover all post-create failures.** run_locked.py:45 creates the shared directory, but try/finally starts only at :56. Failure writing owner.txt, the post-acquisition audit, audit JSON, ledger entry, or temporary setup leaves an orphaned lock. Enter cleanup immediately after successful atomic creation, retain an ownership token rather than substring matching alone, and release only the owned acquisition. Audit after create should still be mandatory. The ledger evidence path at :53 incorrectly says wave17-matrix/inplace/logs instead of matrix/logs.

12. **Heavy-process coverage and temporary paths need explicit handling.** audit():31-36 logs active CPU processes but blocks only named Python/compiler jobs with known ancestry/command lines. A busy workspace powershell or cmd wrapper executing substantial work without a listed descendant can pass the check; explain/extend the recognition so the claimed no-other-heavy-process check is true. Missing/null process metadata should produce an auditable unknown rather than raising during int(None). run_locked.py:55 places compiler caches in matrix/cache and matrix/numba, outside matrix/temp; place run-created scratch/caches under the allowed clone temporary directory. TEMP/TMP variables alone do not enforce confinement; keep recipes explicitly harmless and avoid arbitrary file/network arguments.

## Recommended immediate smoke gates

Before any full matrix: repair fixtures/classification; exercise a successful numeric native path, named decline, expected Python exception, deliberately observed native disagreement through an injected harness-only fake wrapper, swallowed backend exception through an injected harness-only wrapper, mutating/aliasing arguments, synchronous/async generator draining, and builtin aiter/anext. These checks validate the observer itself and must not be reported as compiler coverage. Then run the actual constructs under the shared lock and use only those outcomes in matrix verdict totals.
