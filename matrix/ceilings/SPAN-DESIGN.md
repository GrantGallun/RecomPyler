# Shared read-only bytes and Unicode span mechanism (design only)

S36 requires one mechanism for both kinds after the user chooses a backend. No product capability is implemented by these diagnostics. The large byte ceilings choose borrowed buffers, and the Unicode control will apply the same remaining-time <=2x criterion. This design does not authorize edits in wave16's load/write-back/startup paths.

Represent an exact immutable Python bytes/str value by a pinned owner, data pointer and logical length. Unicode adds the PEP393 one/two/four-byte kind and ASCII flag; bytes has unit width1. Index arithmetic is in Py_ssize_t with pre-addition/multiplication bounds, negative-index normalization and explicit IndexError behavior. Use code points for Unicode indexing, not UTF-8 byte offsets. The owner remains live across every raw access, including calls and exception cleanup. No process-local raw addresses are serialized into AOT artifacts.

Reuse available Numba mechanisms before writing replacements. Installed numba/cpython/unicode.py UnicodeModel already has data,length,kind,is_ascii,hash,meminfo,parent. Its unbox_unicode_str pins the original PyObject through nrt_meminfo_new_from_pyobject. Its standard box_unicode_str always builds a string_from_kind_and_data and hashes it; that does not itself promise original-input identity. A strict wrapper/custom type should reuse the representation and lowering where behavior matches while explicitly preserving parent identity for selected unchanged values, rather than globally changing Numba's type. Installed Buffer ArrayModel supplies meminfo,parent,nitems,itemsize,data,shape,strides, and unbox_buffer adapts the Py_buffer with NRT ownership/cleanup. core/boxing.py box_bytes constructs Python bytes from data/nitems and decrefs NRT; it also does not promise the original parent identity. Exact bytes remains the eligibility restriction. Both kinds therefore need strict owner-preserving return rules around existing representation/lowering. These are source facts, not new runtime verdicts; existing plain-njit fixture outcomes remain the execution evidence.

At entry check exact Python type, required function/builtin/helper bindings and context. A failed pure guard chooses the original region before effects. Do not speculative-call a module property or custom mapping while deciding eligibility. Bindings may later use the existing validated watcher mechanism to reduce entry cost, but watcher availability/invalidation must be proved and measured, never assumed. Custom str/bytes subclasses and effectful context stay on the original/boxed route.

For created results allocate one Python result construction with checked length and Unicode maxchar/kind, fill exclusive unpublished storage, then return it through the same NRT owner model. Keep buffer-lifetime ownership separate from selected-object provenance. Numba Unicode parent is a borrowed field pinned by meminfo for an unboxed input; new strings and views can have parent=NULL. Never infer selected-object identity from matching data pointer/length or from buffer ownership. Carry the exact semantic selected object through branches/phis and each operation's full-slice/concat/join rules. If an unchanged/full-slice operation semantically selects an existing object, return that selected Python object with the required new reference. Track whether a value is an existing owner, a newly owned result, or a temporary view; temporary views may not escape without the proper Python slice/materialization. Empty/single-character caching and multi-line join identity must follow the corresponding CPython operation, not mere value equality. Using standard Numba native-result allocation followed by its usual box would allocate native storage and then copy into a Python object; representation reuse alone does not eliminate that extra allocation/copy. For the intended one-Python-result construction use explicit CPython-result allocation and fill unpublished storage, then attach NRT ownership. If an operation instead needs native temporary storage/materialization, include both allocation/copy costs in its measured route and report it as such. Result construction may resize in a specific prototype; one construction is not a promise of one physical allocation.

A guard failure after observable effects may not rerun the original region from entry. Hoist all facts needed for a native operation before effects, or continue boxed at that operation with the current state and original exception ordering. Revalidate after callbacks where appropriate; a generic guard-miss rerun is only for entry guards before effects.

Operations that can invoke Python callbacks stay boxed with exact evaluation order and error propagation; no borrowed mutable storage may survive a callback without revalidation/strong ownership. Keep the GIL for CPython APIs. Each output/error edge releases new references and NRT owners exactly once; the already-tested managed-object intrinsic pattern provides reverse cleanup and active-error propagation. OOM injection, ambient cyclic-finalizer interleavings, asynchronous mutation, free-threading and subinterpreters require explicit later analyses/tests and are outside these prototype proofs.

First product slice after the backend choice: owner/kind/span unbox-box plus len, checked byte/code-point reads and read-only loops; then slices/concatenation/comparison with strict identity/error gates. Reuse the12 byte-method and23 str-method plain-njit matching fixtures as candidates, not universal acceptance. Five str predicates already differ in return type and need strict bool handling. Every newly native matrix row is rerun with aliases, mutation, exact types, exceptions and callback order; whole-function held-out native count/share and captured/verified/deployed are measured before/after each accepted capability. Preserve the unchanged profitability gate: small-call losers stay in CPython.

Estimated shared work:300-600 lines ownership/type/AOT adapters,500-900 lines initial recognizers/checked operations,300-600 lines integration/regressions, followed by the accepted union suite and relevant paired kernels. These are estimates and pending implementation obligations, not missing-proof reasons to close the step. Product integration that requires an owned wave16 path must be coordinated rather than editing that path here.
