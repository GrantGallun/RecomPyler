# S32 bytes ceiling independent preparation review

Read bytes.c, encode85.inc, matrix/build_ceiling.py, installed CPython 3.14 base64.py and full S32/S33/S34 directions. No workloads were executed and no compiler/behavior verdict is inferred from source. Only this review file was written. The three retained-profile nominations are complete bodies and all are base64; retain that concentration and the 0.000510s bytes leave-out association rather than implying broad library coverage.

## Required fail-first gates / corrections

1. **Noncanonical _85encode tables break the partial-zero fast path.** Exact list/bytes-length guards permit chars[0]=b'!' and chars2[0]=b'XY'. For b=b'\0', pad=False, foldnuls=True, the original emits z for the padded zero word, then replaces final z with chars[0]*5 and truncates to b'!!'. encode_borrowed suppresses z on the last partial word and instead reads chars2[0] twice, yielding b'XY'. Execute this with otherwise ordinary complete lists. Either implement the original final-z expansion exactly or establish canonical table relations before selecting this route. Merely testing the actual entries' byte lengths does not prove the relation. Cover lengths 0..9 and all eight boolean flag combinations, zero and space words, canonical a85/b85 alphabets and altered tables.

2. **Boxed decoders assume a bytes result where the real converter allows bytearray.** _bytes_from_decode_data returns bytearray unchanged. b32_boxed calls PyBytes_Size and PyBytes_AS_STRING; a85_boxed calls PyBytes_Size on combined data that can remain bytearray. Execute valid bytearray(b'MY======') and bytearray(b'87cURD_*#TDfTZ)+T') against originals. Use faithful bytearray operations/conversion or fall back before body effects for non-exact-bytes. Invalid ASCII text, ASCII str, memoryview, bytearray and bytes subclasses need explicit coverage or an advertised exact-bytes restriction; default decoder flags alone do not restrict input type. Borrowed entries already reject non-exact input bytes.

3. **Boxed encoding tail slicing has extra/missing callbacks for non-inert tables.** Original tests chunks[-1] == b'z' (including user rich comparison) and then evaluates tail[:-padding] without calling len(tail). encode_boxed recognizes only exact one-byte z and calls PyObject_Length before a nonnegative-stop PySequence_GetSlice. A custom piece returned through table indexing/addition can expose a missing __eq__, extra __len__ or different slice object. Either restrict boxed tables to known-inert exact shapes before callbacks and delegate everything else, or implement the original rich comparison and a slice with stop=-padding. An error from PyObject_Length also needs checking before another C-API operation.

4. **Base32 output-size arithmetic can overflow signed Py_ssize_t.** b32_borrowed allocates (end*5)/8, whose multiplication can overflow before division. Compute through safe quotient/remainder arithmetic or reject the oversized domain before multiplication. Other output bounds should be reviewed as integer arithmetic rather than relying on allocation failure to avoid undefined behavior. The ascii85 n*4+4 and encode words*5 paths already contain explicit upper checks.

5. **Module/helper bindings are part of eligibility, not only input shapes.** All versions read mutable base64 state, and native versions additionally bypass operations using cached binascii/struct classes and packer. An exact input bytes object alone does not prove convert() returns bytes if base64._bytes_from_decode_data was rebound. A noncanonical _b32rev entry causes borrowed decoding to call convert before falling back to the original, so a rebinding converter that records an event is called twice instead of once. Guard the captured helper/cache/struct/binascii context before effects, or clearly bound the diagnostic to frozen trusted module bindings and avoid claiming those mutations are handled. Treat unusual reverse-map/table objects as fallback before callbacks. Original reverse-table setup tests membership then builds via enumerate; reverse_table instead attempts indexing and builds via sequence indexing, which is equivalent only for its inert captured shapes.

These are concrete witness proposals to execute, not observed failures. Keep accepted corrections and actual red/green artifacts before reporting measured ceilings.

## Ownership and error checks

C local cleanup mostly owns new references and clears temporaries after use. borrowed loops retain s and reverse mapping while borrowing input data, so ordinary exact immutable bytes remain alive under the GIL. Native _85encode reads borrowed list entries and only accepts exact immutable bytes for them; callbacks/GC mutation during allocation remain a separate eligibility boundary and must not be implied solved by element checks alone.

The chained_error helper deliberately keeps the caught KeyError/struct.error as __context__, sets an explicit None cause and suppresses context. That is the relevant shape for original 'raise ... from None'; test it with run_matrix.exception, not only type/message equality. Required error cases include invalid base32 digit, all invalid padding counts and short lengths, internal '=', high-byte invalid ascii85 digits, z inside partial quantum, ascii85 overflow (including a partial suffix completed with u padding), and conversion failures. Compare active exception chains under an existing enclosing handled exception too. Reference/compiled mutations, cache initialization, success/error input refs, returned result refs and finalizers remain actual acceptance gates.

The borrowed ascii85 implementation reserves n*4+4 bytes and shrinks through private _PyBytes_Resize; _85encode similarly shrinks an upper bound. Describe this as one result construction with resize, not a guaranteed one physical allocation or exact-size buffer. Report allocation/peak-memory implications for large inputs; a85's generous buffer can be roughly five times the typical decoded result. _PyBytes_Resize also makes this a CPython ABI experiment, not Stable ABI.

## Existing-pipeline obligation

matrix/build_ceiling.py uses the existing product Toolchain to build an ordinary C extension. That measures a useful hand-C ceiling but does not itself demonstrate version (b) through the nopython/AOT object mechanism established by S35. S32 says 'through the existing pipeline', and S33 says the later subsystem ceilings use its answered object route for version (b).

Include actual managed-nopython/AOT complete-call bridges to both boxed and borrowed helpers, with their boundary costs measured and with fresh-process AOT success/error import checks. Calling exported builtin helpers from typed CPython-API intrinsics is an honest bridge-to-hand-C mechanism probe if labelled that way; it is not automatic source recognition or native buffer lowering implemented in RecomPyler. Do not persist process-local raw function addresses in an AOT artifact. Keep direct-C columns separately to distinguish representation ceiling from existing-pipeline boundary overhead. No product/backend change is authorized by building these diagnostic bridges.

Default a85decode flags and _b32decode casefold=False/map01=None are a legitimate explicitly disclosed slice. Other decoder flags are unmeasured. Encoding promises all boolean pad/foldnuls/foldspaces combinations, so they need actual coverage rather than default-only timing recipes. All three timing recipes must be faithful realistic held-out calls with three alternating pairs under the lock. No BOUND acceptance yet; no prototype was run by this reviewer.
