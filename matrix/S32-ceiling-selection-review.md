## Strings / bytes: three strongest byte-loop cases

Source: C:/Python314/Lib/base64.py:364 (a85decode), :299 (_85encode), :198 (_b32decode). Inputs: wave14-capture/capture/inputs/base64/run_benchmark.py.

- **a85decode.** Final actual reason is bytes argument. Recreate deterministic bytes using Random(12345).randbytes with the benchmark's generation sequence: 20, 127, 3,072, 9,000, 102,400 and 1,048,574 bytes. Use its A85_LARGE/A85_HUGE encodings and the ASCII-string variant actually used by the small recipe. Time one complete decode per call, not a byte-scanning fragment. Boxed version translates the complete loop with PyBytes/PyUnicode conversion, Python boxed integer multiply/add, Python list append, guarded struct.Struct.pack vectorcall, bytes join and slice via CPython APIs. Native version borrows the byte span, scans with checked uint64 accumulator, writes decoded uint32 groups in big-endian order and allocates the final Python bytes once. Preserve z/y special forms, ignored characters, adobe framing, padding, overflow and exact exception behavior. Default-only measurements are a stated slice; do not present them as all option combinations.
- **_85encode.** Its observed capture barrier is size, not merely bytes, but it is the second-hottest actual byte algorithm. Use the exact initialized chars/chars2 tables from a85encode/b85encode, same large/huge byte inputs, and both foldnuls/foldspaces/pad variants occurring in the public benchmark paths. Boxed version preserves struct.unpack, boxed division/remainder, table-indexing, chunk list and join. Native version reads big-endian uint32 words from borrowed bytes, preserves table data and order, emits 85-base digits and shortcut z/y, then applies identical partial-word trimming. Include output allocation and last-word handling in the timed call. Do not replace the benchmark with a C codec that uses a different policy/algorithm.
- **_b32decode.** Final actual reason is bytes argument. Use _b32alphabet and B32_LARGE/B32_HUGE from the retained recipe; include ASCII-string inputs and boundary padding/error checks for correctness. Boxed version preserves the reverse-dict cache, bytes conversion/translate/upper/rstrip, per-character dict lookups, boxed shift/add and to_bytes calls. Native version borrows input, guards a 256-entry inverse alphabet, decodes with bounded 40-bit arithmetic and allocates output once. Validate alphabet/cache identity and casefold/map01 behavior; invalid-byte and padding exceptions remain faithful.

All three are in one program. That concentration must be stated, with a leave-base64-out figure for the subsystem ranking. The byte ceiling does not establish Unicode representation performance. The hottest explicit string-method blocker in the existing data is textwrap.dedent at C:/Python314/Lib/textwrap.py:416, called from SQLAlchemy docstrings: 273 calls, cumulative 0.001078 s, self 0.000544 s. If a Unicode representation is to be chosen now, add this small control with actual SQLAlchemy docstrings; boxed split/isspace/min/max/join versus a borrowed PyUnicode_KIND/DATA scan preserving tabs, blank-line normalization and all Unicode whitespace. UTF-8 bytes alone are not a general Unicode indexing representation.

## C builtins / methods: retain real object operations

The two decimal benchmark entries are the hottest primary entries with explicit final C-call blockers: decimal.getcontext. Their bodies additionally exercise C Decimal operations through numeric slots. They are useful complete-call tests of boxed native control flow, not evidence that one getcontext call owns all their time.

- **bench_decimal_pi** (wave14-capture/capture/inputs/decimal_pi/run_benchmark.py:38). Retain both precisions 9 and 19 and 10,000 pi_decimal calls per precision. The boxed hand version runs the entire pi_decimal loop natively, uses PyNumber_* for actual Decimal arithmetic/comparison and vectorcalls the guarded Decimal constructor/context functions, with correct reference/error handling. Retain changed decimal context and flags. A float approximation is not a native representation ceiling for Decimal; no faithful fixed-double candidate is proposed.
- **bench_decimal_factorial** (wave14-capture/capture/inputs/decimal_factorial/run_benchmark.py:34). Retain context MAX_PREC/MAX_EMAX/MIN_EMIN and n=10,000/100,000. Boxed hand version compiles the recursive factorial control flow and calls the actual Decimal/PyNumber operations, preserving operand dispatch, rounding, context flags and exceptions. A uint64 or floating factorial is not a faithful ceiling. Native arbitrary-precision decimal would require a real exact decimal backend/API, sized separately; do not assume private _decimal internals are available or substitute int factorial.
- **regex_v8 block1** (wave14-capture/capture/inputs/regex_v8/run_benchmark.py:354). It is the hottest actual block in that program by complete cumulative time; block0 is the next useful control (0.008103 s versus block1 0.012095 s). Reuse the real initialized regexs/strings/subcount globals and execute the entire block body with its original counts. Compile loops, guard pattern/callable identity and vectorcall the actual Pattern.search/sub and re wrappers, preserving replacement/count/error behavior and discarded Match allocations. The C regex engine is already the native representation; replacing the patterns with unrelated manual string tests is not faithful. This example may show little gain because its retained library time is large; only the actual three-pair experiment decides.

The raw trace does not isolate time inside individual C call targets or numeric slots. Do not infer interpreter-removal speedup from self_s alone. Conversely (b) not winning proves no gain for that complete function under that input, not that every C-call kernel is inherently unwinnable.

The apparent concurrent_imap generator cumulative 0.525714 s mostly waits on workers and is not a synchronous closure-control ceiling. FastAPI network coroutine closures are excluded from this small no-network ceiling experiment, and the known busy-wait artifact is excluded from rankings.

## Implementation and acceptance cautions

Both hand variants must enter through the existing pipeline's real call boundary and include type/identity checks, boxing/unboxing, Python output allocation and cleanup. Calling the unchanged Python function once from generated code is not version (b); its body loop must actually be translated. Boxed C-API work holds the GIL and handles reference ownership/error propagation correctly. A native buffer variant must retain the original object lifetime and fall back before unsupported external effects.

For each selected function record a/b/c complete-call times, output/exception/state equivalence and the exact native slice delivered. Pick the cheaper route only after the measured BOUND, requiring at least half of the best ceiling as S32 says. Any narrower input or reduced wrapper set needs a DEVIATION/explicit fraction; none of the historical envelope values above is itself an unlocked-time bound.
