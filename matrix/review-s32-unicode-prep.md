## Semantic obligations

The reference is the installed new dedent implementation, not the older regex algorithm. It splits only on LF; excludes empty/isspace-only lines from margin selection; takes lexicographic minimum/maximum; removes only their common ASCII space/tab prefix; normalizes whitespace-only lines to empty; and rejoins with LF. The borrowed common-prefix-of-indent computation appears equivalent for these exact string shapes. Do not treat every Unicode whitespace character as removable indentation on a nonblank line.

Cover empty text, one-line unchanged/no-margin identity, indented one-line slices, all-blank strings, trailing LF, repeated empty lines, equal/prefix-related nonblank lines, CR within a line versus CR-only blanks, mixed tab/space prefixes and U+0000 text. Output/input identity belongs in every route's oracle: a single unchanged exact string should remain selected as original, while multiple-line join behavior must match the reference. Current observe records type, full value and input alias, which is suitable.

The deterministic 300-case grammar is useful but its whitespace alphabet is a subset. For an explicit 'all Unicode whitespace' claim, enumerate code points for which chr(cp).isspace() is true and test each as a blank line and as a prefix before nonblank text. This distinguishes Unicode blank-line normalization from ASCII-only margin removal. Include narrow Latin-1, BMP and astral nonblank content to exercise all PEP393 kinds and output-kind selection.

Boxed line-list references retain borrowed lo/hi. New piece/list/join refs unwind through cleanup. The borrowed path keeps the exact input owner pinned while reading kind/data/length, creates the result only after sizing and fills an exclusive new Unicode buffer. Single-line Substring preserves full-slice identity, including empty string behavior. The existing managed bridge has explicit callable/argument/result ownership, reverse cleanup and active-error propagation. Actual success/error input loops, relative output refcounts, fallback exception chains and fresh AOT/no-Numba identity calls remain required; structural review alone does not accept them.

## Shared SPAN-DESIGN review (S36.4)

Read SPAN-DESIGN.md and exact installed Numba UnicodeModel/unbox_unicode_str/box_unicode_str, Buffer ArrayModel/unbox_buffer/box_bytes and NRT buffer adaptation source. No workloads were run. The stated source facts are correct: Unicode carries data/length/kind/ASCII/hash/MemInfo/parent and pins the incoming Python owner; standard Unicode boxing reconstructs and hashes a Python string. Buffer adaptation carries data/shape/strides and an NRT owner plus Py_buffer cleanup; box_bytes reconstructs from data/nitems. These representations do not by themselves preserve arbitrary selected-input identity.

The shared exact-type, pinned-owner, code-point-kind/length design is suitable for the proposed first read-only slice. Clarify the following implementation obligations before treating it as a complete strict representation:

1. **Buffer ownership and selected-object identity are different facts.** An input owner pins storage, but an offset/shortened view must not box as the whole owner merely because owner is non-NULL. Conversely Numba's new strings/views can explicitly set parent=NULL while sharing MemInfo, so parent alone does not retain selection provenance. Preserve a distinct selected-object identity/materialization rule through branches/phis and operation results. Never infer identity from matching data pointer, logical length or equal contents. Full slices, unchanged concatenations, joins, selected Boolean operands and fresh outputs need operation-specific CPython rules. Views may remain native only while their owner remains live and need a real Python slice/materialization on escape when that operation creates one.

2. **Reusing native lowerings can imply a second buffer/copy.** Installed Unicode native constructors allocate NRT storage; standard boxing then creates Python Unicode from that storage. Bytes boxing similarly copies. The single-result-construction goal needs either direct unpublished PyBytes/PyUnicode result allocation with an NRT-owned Python owner, or an explicit native-storage-then-materialize path whose extra allocation/copy is counted. Reusing the existing model/lowering does not automatically make return boxing zero-copy. Keep identity-preserving owner returns separate from newly allocated results and benchmark actual boundary costs.

3. **Guard placement must account for completed effects.** An entry guard can safely select the original before effects. A new operation/range/ownership guard failing after a Python callback or mutation cannot rerun the whole original function. Prove/hoist the necessary guards before observable effects, or continue through the boxed operation at the current point. After callbacks, dependent module/callable assumptions may need revalidation even though pinned exact bytes/str data remain immutable. This is an analysis to implement, not a missing-proof reason to close a capability.

4. **Reuse the error contracts deliberately.** Installed unbox implementations are evidence of a model, not a complete strict error blueprint. Preserve explicit NULL/allocation checks and the installed MemInfo owner-increment contract, release Py_buffer cleanup in the correct order, and keep each owned ref/MemInfo release exactly once on success and exception edges. The already-reviewed managed-object prototype supplies tested ordinary error patterns; OOM injection remains unproved in diagnostics and a separate product obligation. Do not extend Buffer eligibility beyond exact immutable bytes without proving lifetime/exporter behavior.

5. **Units and domains stay explicit.** Unicode indexing is by code points with one/two/four-byte storage; slices use logical offsets, and allocation checks include terminator and width multiplication. Include embedded NUL and lone surrogate strings in future strict operation gates; exact Python str is not limited to UTF-8-encodable text. Bytes cover all 256 byte values and index to exact Python integers. Subclass/custom __index__/slice/equality hooks stay boxed unless separately modeled. Same-type comparisons and hashing must preserve exact public result types and CPython semantics; the plain-njit predicate differences already show why type checks matter.

The source-estimated 300-600 ownership/type/AOT adapter lines plus 500-900 operation and 300-600 integration/regression lines are plausible initial planning ranges, not evidence that alias/escape/control-flow analysis has been implemented. Keep the first slice narrow (entry, len, checked reads, read-only loops), then add escape/materialization and new operations under executed gates and the full acceptance protocol. No extra backend or product change is authorized by this design review. No additional concrete design blocker was found once these obligations are made explicit.
