# Native guard audit capability: DESIGN54 proof inputs

Matching installed CPython3.14.4 source is copied read-only from its primary tag into cpython3144-sysmodule.c and cpython3144-lock.c. Source URLs: https://raw.githubusercontent.com/python/cpython/v3.14.4/Python/sysmodule.c and https://raw.githubusercontent.com/python/cpython/v3.14.4/Python/lock.c . Installed Include/patchlevel.h identifies3.14.4.

sysmodule should_audit considers runtime C-hook head, current interpreter Python-hook pointer and DTrace. PySys_AddAuditHook publishes under runtime.audit_hooks.mutex even when called without a current thread state. Python sys.addaudithook mutates only the attached interpreter list while running Python with the GIL. Therefore the fast checker must decline any hook pointer or DTrace build, nonblocking-acquire the exact header-defined global audit mutex before reading head, and retain it through its no-allocation/no-callback/no-detach interval. Busy means None before any metadata read. This handles native concurrent registration rather than treating an earlier pointer observation as permanent.

Installed pycore_lock.h PyMutex_LockFast is one atomic try; it never takes a wait/detach path. Public PyMutex_Unlock uses atomic fast release or _PyMutex_TryUnlock -> _PyParkingLot_Unpark, not a Python callback or GIL-detach path. No held-interval operation acquires the audit mutex or dispatches an audit event: native fields/dict/Unicode comparisons and existing immortal bool/None returns only; PyType_GetDict in matching typeobject.c only balances references to the still-owned dictionary. All native scan returns flow through one outer unlock wrapper. Scope is exact3.14.4 headers, GIL build, no DTrace; other configurations select Python. Future support needs its own source/ABI check, never guessed offsets.

The observer-present path returns None before scanning, preserving original ordered getter events, hook exceptions and mutations. Tests install hooks only inside fresh child processes because sys.addaudithook cannot be undone. No hook/allocator/runtime setting is changed in the coordinator or user process. Guard staticmethod unwrap additionally rejects Py_AUDIT_READ/Py_RELATIVE_OFFSET.

This is a proposed capability requiring independent review and fail-first tests, not an activation/performance claim.

Certification is limited to this freshly built installed Windows x64 release CPython3.14.4: compile-time exclusions include free-threaded, DTrace, debug, trace-refs and statistics configurations; absent build signature also disables the capability. Before dereferencing any private runtime field guard_begin compares public Py_Version and the full Py_GetVersion build signature against the setup.py compiled sys.version. The fresh build receipt freezes all installed headers, full runtime signature/configuration and the actual DLL containing Py_GetVersion (read-only WinAPI module identification and SHA256), before and after compilation and installation. This is local extension ABI evidence, not a claim that arbitrary custom builds sharing a version number are compatible.
