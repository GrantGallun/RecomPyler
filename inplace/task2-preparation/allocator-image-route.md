No DLL API was invoked, allocator queried/changed, native probe built or workload run.

Installed pycore_runtime_init.h initializes `_PyRuntimeState.allocators.obj_arena` with `_pymem_allocators_obj_arena_INIT`; pycore_pymem_init.h defines that initializer as NULL context and the default `_PyMem_ArenaAlloc`/`_PyMem_ArenaFree` callbacks. Their missing named exports need not force treating the first observed live callback as a default.

Future implementation can compile `offsetof(_PyRuntimeState, allocators.obj_arena)` and the nested field sizes from the installed headers, locate `_PyRuntime` through the loaded image's actual export table, and read the corresponding *original file image* initializer words. Validate the file identity, PE section bounds, preferred-base relocation records and executable target sections; convert the initializer function words to RVAs and map those RVAs into the loaded image. Require the original context to be NULL and the live arena tuple to match these authoritative defaults. Fail closed if the initializer is absent/zero/unmappable or source/header/binary identity is uncertain. Support only the exact ABI whose independently verified headers and DLL are sealed. This is an image-derived default certificate, not an import-time live-pointer baseline.

The standard RAW/MEM/OBJ callback tables also exist in that original initializer; a future resolver may compare their complete ctx/function records against the live table after handling the debug wrapper's image-relative context pointers. The existing exported default-name comparison remains an independently checked option outside the raw interval. Getter mutex paths can detach, so no getter follows graph pinning. Do not read live multiword allocator tables concurrently without the required lifetime/synchronization proof.

Remaining proof to build: postinitialization allocator setters in other interpreters or attached native threads; single-interpreter/GIL capability and prevention of a concurrent new interpreter; exact callback call graph including arena/system/free behavior; allocation-failure ordering and original-operation observer/safepoint/token lifetimes. The official Python 3.14 memory C API requires postinitialization allocators to wrap the current allocator and allows allocator functions to be called across independent interpreter GILs. A one-time default check alone does not close that race. The ordinary GIL/thread-state API contract may justify a guarded single-interpreter interval, but that is an inference needing source/API review, not current certification.

Independent design review (prepared_review, read-only): the image-initializer resolver is viable, but main-GIL ownership does not stabilize the interpreter list. PyInterpreterState_New is explicitly callable without an attached state (https://docs.python.org/3.14/c-api/subinterpreters.html#c.PyInterpreterState_New); matching installed-header version3.14.4 pystate.c protects creation/deletion by runtime.interpreters.mutex and documents mutation while the GIL is held (https://raw.githubusercontent.com/python/cpython/v3.14.4/Python/pystate.c). The proposed constructive capability is nonblocking PyMutex_LockFast on interpreters.mutex before any pin, require current==main/head==main/next==NULL, then nonblocking acquire allocators.mutex, compare full live callback/context tables against authoritative file defaults and retain both through the certified attached-thread/no-callback interval. Any busy mutex declines before pins; every exit releases before observers. Matching obmalloc.c setter paths use the allocator mutex while ordinary allocation dispatch reads callbacks directly (https://raw.githubusercontent.com/python/cpython/v3.14.4/Objects/obmalloc.c). Must still prove lock order, no recursive mutex acquisition in the actual allocation/free paths, unlock wakeup behavior, every failure path and no observer/detach while held. This is a synchronization implementation route, not approval to hold arbitrary locks across callback-capable code. No API/build/workload/edit by reviewer.

PE proof checklist from reviewer: header-derived nested offsets/sizes and exact binary/header ABI; real loaded-image ownership; bound/overflow checks; reject forwarded exports and unmapped/zero/runtime-only initializer fields; verify every relocation and same-image executable function RVA under ASLR; exact original NULL ctx; open/pin one original file snapshot instead of path re-reading across replacement; all RAW/MEM/OBJ/debug context tables and arena/fallback callback paths; tracing/stats/CRT/system hooks and original-operation allocation failure ordering. Each is required analysis/implementation, not a reason to close the task as missing proof.
