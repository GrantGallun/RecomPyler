# Future numeric store mechanism (unimplemented)

S49 permits exact int/float/complex object identity and sharing to differ, while type/value must remain exact. A closed callback-free flat numeric region may therefore reuse an existing UNIQUE exact numeric box as storage, if no other Python owner can observe that box and native scalar locals preserve their logical old values. This is a candidate physical protocol, not an accepted proof or implemented rule.

Candidate float-list store: exact float target, Py_REFCNT==1 and nonimmortal; journal raw old bits plus pointer before mutating header-derived ob_fval. Root list and unchanged item edge keep that object alive throughout the interval; no extra item INCREF masks uniqueness. Native reads guard kind and load current bits; earlier unboxed scalar locals retain their own old numeric values. Numeric is/id observations, callbacks, escaped native object references, returned containers and arbitrary reference stores already decline. Shared float with identical new bits can be a no-op; a changed shared float declines. No new numeric allocation or old-object destruction occurs in this interval.

Candidate int-list store: bounded exact unique nonimmortal int; new magnitude digit count must fit the current known allocated lower bound from old digit count. Use installed PyLong sign/digit definitions, not offsets, with safe uint64 magnitude for INT64_MIN. Journal old tag/digits; never mutate cached small ints/bools. If both old and new int values are proven cached immortal objects, pointer replacement can avoid allocation/deallocation. Other shared/cache-to-large cases decline. Refcount/digit/tag/immortality facts need installed-source verification and executable negatives.

Raw bounded journal allocated before borrow, no element walk, no Python objects in journal. Log every write and restore reverse order; bounded capacity exhaustion returns raw failure/undo before Python replay. Do not free/allocate inside the borrow. Repeated stores must remain correct after prior mutations, with aliasing preserved for all nonnumeric objects. Read-only signatures should not pay this journal cost; use a writable schema/type or explicit immutable capability metadata derived from Unit.writes.

Review obligations/tests before acceptance: source-visible old values retained in native scalar locals, external numeric aliases (RC>1) refuse, two list cells holding same number refuse changing it, -0/NaN payloads, int digit transitions and small-int singletons unchanged, partial stores/overflow/bounds/native error/full rollback, root/list identity, profile-time root/type/refcount changes. C ref-tracer/tracemalloc/custom allocator observation and CPython immutability assumptions must be resolved or conservatively excluded; avoiding in-interval allocation alone does not prove every observer equivalent. Keep allocator-capability.md limitations for cases that still need a new box. Do not claim this eliminates the broader allocator proof.

Field stores could later use the same unique-box rule, but additionally need GenericSetAttr/descriptor/dict-watcher guards and dynamic slot reads after stores (the current field-only payload is a read snapshot). Shared cached-int pointer updates require correct managed/inline storage semantics and rollback. This is later than saved flat AOT; no product code exists for it.
