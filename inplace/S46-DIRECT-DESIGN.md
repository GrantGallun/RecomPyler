## Callback-free C execution interval

Compile ABI/layout facts from the installed CPython headers; include build/runtime/header/source/plan/capsule fingerprints. No persisted raw address or copied layout constant. Reject free-threaded builds and unknown allocator/helper capabilities. A successfully built optional extension alone grants no entry.

Allocate raw capacity and observer-capable resources before borrowing nested objects. The actual C profile entry happens before the fresh walk. Then resolve live weak/global dependencies, validate exact supported layouts/kinds/ranges and alias topology, canonicalize physical cells and pin only for the execution interval. Do not retain unrelated graph roots across a later callback or output allocation. An underestimated capacity returns a decline before borrowing/publication, or a checked rollback status after stores; no hidden Python growth inside the interval.

The C walk constructs the same logical handles/topology for ordinary arena fallback, but omits eligible numeric payload staging. It maps a certified live slot to its physical field/list cell and pinned owner. Repeated aliases use one physical-cell entry. Read-only cells may initially retain the exact box; stores require fresh physical-cell dereference. Exact INT remains signed64 with header-derived unsigned magnitude decoding and checked sign, including endpoints and2**53+1, never a double round trip. MIXED preserves its existing domain and declines outside it.

Lower typed numeric accesses only after R8. Keep topology/tag/header access distinct from numeric payload loads and retain ordinary private-temporary slots. Every helper that copies/iterates/fills/slices numeric cells has an explicit transfer/effect rule or causes decline. No generic F/I rewrite and no noalias metadata. Shared raw arena views retain their alias relationship.

Use the real no-NRT machine adapter with retained executable libraries/environment. Extend its ABI with authenticated context/slot-map descriptors shared by JIT and saved AOT. Source/plan/header/runtime/capsule binding is checked before the final walk. There are no Python callbacks, profiler timestamps, output allocations or Python result conversion inside the raw interval. Native status, rollback and cleanup return primitive data; conversion begins after unrelated pins/maps are released. A native success followed by conversion/profile failure is zero completed calls.

## Stores, topology and observer order

The first store to a canonical physical numeric cell records its exact old reference/value; repeated stores share that undo record. Preallocate any publication boxes and journal capacity using the explicitly proved allocator/observer capability. Exact bool/None use their original singletons. Numeric identity exemption permits a new equal box, never mutation of an existing caller numeric box or another alias's value.

On every checked failure, restore all published cells and buffer bytes before releasing the journal and before fresh Python replay. Test overflow, bounds, native exception, capacity/allocation failure and recursion exit after partial stores; preserve CPython evaluation and exception order. Exception fallback must not apply a successful partial store twice.

Topology/object-reference replacement additionally requires the old value's natural-root and observer-safe retirement proof. A held pin or undo record can delay a weakref callback/finalizer; absence of __del__ on the immediate owner is insufficient. Unknown root/alias/watcher/descendant observer facts decline before publication. Do not claim Richards object-link stores are covered by a numeric-cell-only journal. Dict watchers, reallocation and arbitrary callbacks remain explicit unsupported cases until their proof exists.

Readonly borrowed input cells may coexist with arena writes only where the transitive may-write and topology proof excludes every alias that can change the cell/path. Known private allocation alone does not prove its returned nonnumeric owner or lifetime. Outputs requiring arbitrary observer-capable allocation are outside the raw interval; exact allocation/finalizer parity remains an acceptance obligation.

## S54.9 interpreter fallback boundary

The initial direct interval still permits no Python callbacks. In-place data alone does not authorize a fallback call while a speculative journal or borrowed view is open. Before an interpreter call, complete/commit the prior segment, materialize any required nonexempt/private argument owners, retire old roots only where proved observer-safe, release every Py_buffer/map/pin and scoped view, and invalidate all cached field/shape/binding observations. The interpreter then sees exactly the committed live state, and may resize, mutate, replace definitions or re-enter the same region. The next segment constructs a fresh context and revalidates on first touch; it re-reads values rather than restoring a pre-call cache.

After an effectful interpreter call, exception or result-type guard failure must not replay the function from entry: earlier stores/calls are already committed. A continuation/deoptimization point or an independently proved replay-safe call is required. The direct runtime supplies interval close/commit and fresh reopen facts; wave18 supplies fallback-call continuation/effect handling and uses the shared managed-object owners. Until both sides exist, the earlier no-converted-state condition remains. This is a future consumer interface, not current capability.
