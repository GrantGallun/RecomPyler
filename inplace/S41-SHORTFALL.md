# Step4 shortfall investigation (development source)

The complete source-pinned three-pair comparison is in s41-fixed-development-v1/complete.json. Field/comparison improves7.059526 to5.806244us; scalar arithmetic improves4.710888 to1.964356us. Python medians after are0.029102/0.024444us. These are gains, but the requested well-under1us/Python-call target is not met. This snapshot precedes the retained-variant rule and is not final acceptance.

The field improvement removes less than half of the entire before-call time. It is not evidence that half the entire call was a removable fixed-cost bound: the instrumented70 table retains observer overhead and cannot be subtracted from an ordinary call. Its largest named remaining operation is graph loading. Source inspection and independent review agree on why it remains: the emitted body consumes F/I arena values, whereas direct.Summary.read_only only excludes stores/observers/unknown effects. It does not supply live field addresses. Region.load/_Loader and _heap.c.load_instance freshly validate class/dictionary/numeric kinds, deduplicate aliases, stage values and retain the loaded graph. Skipping that work with this native signature would consume stale input. The replacement is a fresh installed-header layout/pin/direct-load/token interval, which is Step2 implementation work, not an impossibility claim.

The scalar rule avoids graph load, arena setup, recursive-frame scanning and unloader work. It still runs Python Region.__call__, argument binding in attempt, primitive validation, live dependency guards, the compiled dispatcher call, result conversion and completion accounting. The separate scopes in70 name these costs but are observer-retaining, so they do not establish additive causal savings or a measured lower bound. The observed1.964us is the current implementation's result, not a proof that a C entry cannot be faster. Any vectorcall/raw-entry replacement must preserve dynamic Region/resolver/attempt behavior, the actual native completion audit, authenticated AOT restore and observer/counter semantics; task2-preparation/future-step4.md records those concrete obligations.

create_gc_cycles(100,20) returns a new list of100roots into2100new Node instances and4200next/prev references. Current read-only scalar result conversion is deliberately sized only for a primitive result; it does not pretend this returned list is primitive or discard its identity/cycles. Replacing reconstruction requires source-ordered object allocation, observable GC/finalizer boundaries and continuation after visible progress. These are mechanisms still to implement, with the existing non-vacuous counterexamples in task2-preparation/future-step4.md; deleting conversion is unsound.

Lifetime/allocation checks remain for objects the current loader can copy or output conversion can create/retire. Removing them solely because the region never stores would not prove object lifetime/observer equivalence. No further native guard variant is proposed under S37. Kernel recovery and the six-region/33-program results remain to be measured on final frozen source. No shortfall is relabelled accepted, and no first-lookup, output-conversion or deployment gain is inferred from these two calls.
